# 選択テキスト修正学習 Windows QA（#44）

## 自動テストとの境界

バックエンドでは、修正元履歴が欠落・失敗・音声入力以外の場合の拒否、候補と履歴の不一致、保存データのvalidator、注入失敗のエラー伝播を単体テストする。実アプリのUI Automation取得、保護入力判定、dialogのフォーカス移動、キーボード操作、クリップボードの外部更新競合はWindows UI境界のため自動テストでは保証せず、本書の手動QAで確認する。

## 前提

- 設定の「修正学習」を「保存前に確認」にする。
- 「選択テキストから修正を学習」が既定の `Ctrl + Shift + F8` であることを確認する。
- 直近30分以内に成功した音声入力履歴を2件以上用意する。

## 基本フロー

1. Notepadで、直近の音声入力結果をキーボードで修正した文章を選択する。
2. Notepadにフォーカスがあるまま `Ctrl + Shift + F8` を押す。
3. KoeTypeが選択取得後にだけ前面へ移り、確認dialogを表示することを確認する。
4. 同じアプリの履歴が先、次に新しい履歴の順で最大5件表示され、別アプリ候補には「別アプリ」と表示されることを確認する。
5. 候補を切り替え、元の出力と選択テキストが並列表示され、古い候補のpreview/artifactが残らないことを確認する。
6. 候補が1件でも自動保存されず、元と選択が同一なら保存できないことを確認する。
7. artifactと適用範囲を明示選択して保存し、設定の修正学習管理に即時表示されることを確認する。

## キャンセル・競合・期限

- dialogでEscape、キャンセルボタン、背景クリックをそれぞれ試し、pendingが破棄されNotepadへフォーカスが戻ることを確認する。
- 録音中および処理中にF8を押し、録音へ影響せず固定エラーになることを確認する。
- 修正学習がオフの場合、prepareと既に開いたdialogからの保存の両方が拒否されることを確認する。
- dialogを10分超開いた後、previewまたは保存が期限切れとして拒否されることを確認する。
- F8を連打しても複数dialogや複数pendingが作られないことを確認する。

## 選択取得・クリップボード・保護入力

- 既存クリップボードへテキスト・画像を設定し、Notepad選択からF8を実行後も元の内容が保全されることを確認する。
- コピー中に別アプリがクリップボードを更新した場合、外部更新が保全され、確認dialogに復元見送りの警告が表示されることを確認する。
- パスワード欄でF8を押し、本文を取得・表示・履歴保存せず、固定エラーだけを表示することを確認する。
- 選択なし、複数選択、20,000文字超、UI Automation非対応アプリで、それぞれ本文を含まない明確なエラーになることを確認する。

## アクセシビリティ・データ境界

- dialogへフォーカスが移り、候補radio、artifact入力、保存、キャンセルをキーボードだけで操作できることを確認する。
- dialogが `role="dialog"`、`aria-modal="true"`、見出し参照を持ち、エラーがスクリーンリーダーへ通知されることを確認する。
- 選択本文がconsole、Rust log、エラー、音声入力履歴へ追加保存されないことを確認する。
- 保存前の説明に、平文ローカル保存と語彙・文体例の外部API送信可能性、アプリ範囲が表示されることを確認する。

## 設定とrollback

- 4つの通常ホットキーの任意ペアを同じキーにし、保存が重複エラーになることを確認する。
- 他アプリが占有するキーへ変更し、登録失敗後も以前の4つのホットキーが利用できることを確認する。
- アプリ再起動後もF8設定が保持され、旧settingsデータでは既定のF8へ安全に移行することを確認する。
