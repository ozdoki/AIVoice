# Escape録音キャンセル設計・QA

Issue #34/#35で追加した録音破棄経路と、Windows実機で未確認の項目を記録する。

Escapeと通常停止は同じatomic gateのCASを競う。Escapeが先なら`CancelRequested`、停止が先なら`ProcessingCommitted`になり、先に成功した側を優先する。UIイベント配送や`RecordingState`の別更新との間に判定窓を作らない。commit後のEscapeはgateを変更できず、終了時と次回録音開始時に`Accepting`へ戻すため次セッションへ持ち越されない。

キャンセル時は外側のRealtimeタスクをabortして完了を待つ。Realtime内部の音声送信タスクはabort-on-dropで親に所有され、親だけが終了して送信処理が残る状態を作らない。

## キャンセル経路

通常停止とは別に、録音中のセッションだけを破棄する。

1. `session_action`でstart/stop/cancelを直列化する。
2. 録音中の`SessionController`を一度だけtakeする。
3. キャプチャへ停止を通知し、Realtimeタスクをabortする。
4. キャプチャ終了を待つ。失敗しても通常停止へフォールバックしない。
5. triggerを解除して必ずIdleへ戻す。
6. Recoveryのメタを完了扱いにしてから一時ディレクトリを削除する。削除に失敗しても、メタ更新に成功していれば復元候補へ表示しない。両方に失敗した場合はエラーを通知する。
7. ASR、Polish、スニペット展開、注入、履歴、利用量記録は呼ばない。

自動テストでは、キャンセルがセッションを一度だけ破棄してIdleへ戻すこと、Realtime taskをabortすること、キャプチャ失敗時にも通常停止へ移らないこと、stopとの競合で片方だけがセッションを取得することを確認している。注入失敗の伝播はfake injectorで確認している。履歴・利用量・Recovery削除失敗時の画面通知、およびオンボーディングからの実操作はTauri/Windows境界を含むため、下記の手動QA項目として残す。

PTT key-up、通常停止、Escapeキャンセルは同じ排他制御を使う。先に録音セッションを取得した操作だけが実行され、後続操作はIdle/Processingを見て何もしない。

## Escape監視方式

| 方式 | 対象アプリへのEscape | 登録期間 | 判断 |
| --- | --- | --- | --- |
| 一時的な`RegisterHotKey` | 登録中は消費できる | 録音開始後から停止・キャンセルまで | 採用 |
| `GetAsyncKeyState`ポーリング | 対象アプリにも届く | ポーリング中 | 不採用（録音中の対象アプリへ副作用） |
| 低レベルキーボードフック | 抑止可能 | フック寿命の管理が必要 | 不採用（侵襲性と障害範囲が大きい） |

既存ホットキーワーカー上で`MOD_NOREPEAT + VK_ESCAPE`を一時登録する。Escapeを検出したら、キャンセルイベントを送る前に登録を解除する。この一回性とバックエンドの録音状態確認により、長押し・連打・PTT解放競合を重複処理しない。

Escape登録に失敗しても録音機能は継続する。メイン画面へ非致命的な警告を表示し、手動停止とバックエンドのキャンセルcommandは利用可能なままにする。

## 通知

キャンセル成功時は`state=idle`、`phase=cancelled`を配信する。メイン画面は約1秒後にIdle表示へ戻し、FloatingBarは「録音をキャンセルしました」を表示して約1.2秒後に隠れる。オンボーディングのテスト録音も共通の開始・キャンセル経路を使い、同じ短時間通知を表示する。

## 手動QA手順

1. 録音していない状態で対象アプリのメニューやダイアログを開き、Escapeが通常どおり動作することを確認する。
2. PTT、Rawハンズフリー、Polishハンズフリー、メイン画面の手動録音、オンボーディングのテスト録音を個別に開始する。
3. 各録音中にEscapeを押し、対象アプリ側のEscape操作が起きず、約1秒のキャンセル通知が出ることを確認する。
4. Escapeを長押し・連打し、通知とキャンセルが1回だけであることを確認する。
5. PTTを押したままEscapeを押してからPTTを離し、ASR・挿入が開始されないことを確認する。
6. 停止操作とEscapeをほぼ同時に行い、停止またはキャンセルの片方だけが実行されることを確認する。
7. 履歴、利用量、Recovery一覧にキャンセルした録音が追加されず、直後に次の録音を開始できることを確認する。
8. Processing中と処理完了後にEscapeを押し、KoeTypeが反応せず対象アプリへ届くことを確認する。

2026-07-15の最新Tauri production releaseで、Notepadを前面にしたまま`Ctrl + F1`でRaw録音を開始し、約1.2秒後に今回は意図的にEscapeを押した。KoeTypeを再表示してIdle（待機中）へ戻っていること、ASR・自動挿入へ進まずNotepad本文に新規挿入がないことを確認した。これをNotepadのRaw録音キャンセル成功証跡とする。以前の意図しないEscape操作は成功証跡に含めない。録音外Escape、長押し・連打、PTT解放競合、他モード、履歴・利用量・Recovery一覧の目視確認は未確認のままとする。
