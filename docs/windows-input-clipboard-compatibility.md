# Windows入力・クリップボード互換性

通常入力、履歴・Recoveryからの再注入、選択テキスト音声編集の確定置換は、すべて変換結果をUnicodeテキストとしてクリップボードへ設定し、`Ctrl+V`で注入する。`KEYEVENTF_UNICODE` (`VK_PACKET`) はIMEや予測変換に介入されるため、ユーザー入力経路では使わない。

## 出力の契約

出力注入は入力前のクリップボードをsnapshot・復元しない。画像、private format、非`HGLOBAL`形式などがあっても、結果の設定を妨げない。成功、`SendInput`の0イベント、部分送信のいずれでも、最後に設定した変換結果はクリップボードに残る（外部プロセスがその後更新した場合を除く）。

貼付前に結果のclipboard sequence/ownerと完全一致するUnicode本文を確認する。不一致または所有状態を確認できない場合は貼り付けずに中止し、本文を診断へ含めない。対象windowは送信直前・直後に確認する。UIPIにより高い整合性レベルのアプリへ`SendInput`できない場合があり、直前確認と送信、貼付先の読取の間のTOCTOU raceはWindows API上残る。

`SendInput`が4イベントすべてを送信した後は二重入力防止のため成功扱いにし、直後のフォーカス変化は警告として返す。0イベントと部分送信は自動再試行しない。部分送信ではキー解放を試みる。いずれのエラー・警告にも変換本文や既存クリップボードの内容を含めない。

## 選択取得との違い

選択テキスト取得の`Ctrl+C` fallbackだけは、ユーザーの既存クリップボードを保全するため`ClipboardSnapshot`を使う。Copy後はコピー元アプリがownerになるため、既知のcopy sequence一致を条件に復元し、KoeType owner一致は要求しない。このsnapshot/restoreは出力注入には使わない。

## Windows実機QA

1. 空、テキスト、HTML/RTF、画像、Explorerファイル一覧などをクリップボードに置く。
2. Notepad、ブラウザ、Electron、Terminalへ日本語・絵文字・複数行を通常入力、履歴再注入、Recovery再注入、選択置換で注入する。
3. すべて`Ctrl+V`で一度だけ入力され、続けて貼り付けると変換結果を貼り付けられることを確認する。
4. 権限差などで送信を失敗させ、0/部分送信でも変換結果がクリップボードに残り、自動再試行されないことを確認する。
5. 選択取得のCopy fallbackでは、外部更新がない場合に元のクリップボードが戻り、外部更新は上書きしないことを確認する。

新規依存はない。既存の`windows` crate、`arboard`、選択取得に限定したsnapshot/sequence guardを使用する。
